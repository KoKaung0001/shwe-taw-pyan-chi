## Data contract delivered in M1

The versioned store contains opening balance/reference/timezone; income/expense transaction IDs, amount/currency, category/counterparty/source and separate OCR review metadata; schedule rule IDs; stable occurrence IDs; original due date; payment date/amount/status and confirmation status; lightweight correction history; duplicate pair review fingerprints. An occurrence has at most one linked payment, and a payment cannot belong to multiple occurrences. Rules do not count as transactions. Overdue is derived. Pure selectors and an injected Clock are used. Zod validates writes and rehydration, with a visible recovery notice for invalid, corrupt, oversized or unknown-version saved data. Same-day date-only payments require an explicit opening-balance classification. Unknown persistence versions reset synthetic data until a tested migration exists.

## Non-functional acceptance

Responsive at 360, 768 and 1280 px, no horizontal overflow; keyboard navigation, visible focus, labelled controls, accessible current route and reduced motion. Target WCAG 2.1 AA, with manual assistive-technology review still needed. Keep UI/state/domain/services separated; strict TypeScript. No secrets, trackers, remote fonts, real financial data or backend. Later images stay in-browser, text is escaped, inputs validated.

## Delivery sequence

M0 shell/tooling/docs; M1 data contracts, reference-point tests, clock and validated persistence; M2 manual transactions, opening-balance workflow and linked corrections; M3a one-time schedule lifecycle; M3b monthly generation and catch-up; M4 simulated upload/review; M5 dashboard, outstanding views and forecast with regression scenario; M6 insights, duplicate review and grounded chat; M7 P1 readiness and category suggestions; M8 end-to-end polish/security/demo; P2 only subsequently. M7 readiness uses explicit record checks and a persistent, user-maintained document checklist; category suggestions are optional and never override user selection. M8 expands browser acceptance, verifies the production CSP and documents a synthetic-data demo. Review each milestone before starting the next. M0 implements no financial functionality.
