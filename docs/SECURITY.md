# Security boundaries

This is a local, synthetic-data frontend prototype with no backend, financial integrations, analytics or secrets. The demo sign-up flow stores account email, display name, and salted PBKDF2-SHA-256 password hashes in this browser's local storage. Passwords are not stored in plaintext. The in-memory sign-in session ends on reload; accounts do not sync across browsers or devices. Client-side checks are not a security boundary, and browser storage is not encrypted, so this is not suitable for real financial accounts. Dependencies are locked; CI runs `npm audit --audit-level=high`. Assets and fonts are local. The production HTML policy restricts scripts, styles, connections, images, forms and objects to the app origin, with browser-local blob/data images allowed for receipt preview. Vite's development server adds loopback HMR WebSocket and inline-style exceptions only while serving; the production build does not include them. `npm run verify:csp` checks the built policy. Frame embedding restrictions require host response headers (`frame-ancestors 'none'`) because meta CSP cannot enforce that directive. Configure those at deployment; deployment is outside this milestone.

The prototype validates inputs and persisted data, keeps images local with revoked object URLs, renders untrusted text as text, recovers visibly from storage errors, and does not log financial data. M4 validates JPEG/PNG/WebP type, non-empty size and a 5 MB maximum before previewing with an object URL; the URL is revoked on replacement/unmount and image bytes never leave the browser or enter persistence. The readiness checklist stores only user-selected yes/no status and never uploads document files. Assistant answers and category suggestions are deterministic local rules. Use synthetic records only; browser storage is not encrypted and is not suitable for real financial information.

Production is out of scope. Before real data: OIDC/MFA, per-user isolation, encrypted transit/storage, secret vault, audit trails, rate limits, upload scanning, backups, retention/deletion, prompt-injection defenses with vetted read-only tools, a production host CSP including `frame-ancestors 'none'`, and qualified review of applicable Myanmar financial/privacy requirements.
